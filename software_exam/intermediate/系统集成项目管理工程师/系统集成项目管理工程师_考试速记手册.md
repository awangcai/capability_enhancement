## 第一章 项目管理一般知识 ★★

### 1.1 项目的基本特点

**记忆口诀：临独渐**

- **临时性**：有明确的开始和结束时间（不等于时间短）
- **独特性**：每个项目都是唯一的
- **渐进明细**：随着项目推进，信息越来越详细

### 1.2 项目目标 ★★

- **分类**：约束性目标、成果性目标
- **特性**：多目标性、优先级、层次性

### 1.3 项目管理知识体系 ★

| 体系 | 来源 |
|------|------|
| PMI PMBOK | 美国项目管理协会 |
| IPMA ICB | 国际项目管理协会 |
| PRINCE2 | 英国政府 |

### 1.4 项目干系人 ★★

- **项目经理**：负责项目日常管理
- **PMO（项目管理办公室）**：提供支持和标准
- **其他干系人**：发起人、客户、团队成员等

### 1.5 项目组织方式 ★★★

| 组织形式 | 项目经理权力 | 资源可用性 | 特点 |
|----------|------------|----------|------|
| 职能型 | 很小/无 | 很少 | 多头领导 |
| 弱矩阵 | 较小 | 较少 | 类似职能型 |
| 平衡矩阵 | 低到中 | 低到中 | PM权力=职能经理 |
| 强矩阵 | 中到高 | 中到高 | PM权力较大 |
| 项目型 | 很高 | 几乎全部 | PM全权负责 |

### 1.6 项目生命周期 ★★

- **四阶段**：启动→规划→执行→收尾
- **产品生命周期** vs **项目生命周期**：产品生命周期包含多个项目生命周期

### 1.7 五大过程组 ★★★

**记忆口诀：启规执监收**

1. **启动过程组**：确认项目存在
2. **规划过程组**：制定计划（过程最多）
3. **执行过程组**：完成计划中的工作
4. **监控过程组**：跟踪、审查、调整（贯穿始终）
5. **收尾过程组**：正式验收

## 第四章 范围管理 ★★★

**记忆口诀：规收定创核控**

### 4.1 基本概念 ★★

- **项目范围** vs **产品范围**：
  - 项目范围：为完成项目需要做的工作
  - 产品范围：产品的功能和特征
- **范围基准** = 项目范围说明书 + WBS + WBS字典

### 4.2 创建WBS ★★★

**WBS（工作分解结构）** 是考试重点中的重点！

**分解原则（10条核心记住以下几条）**：
- **100%规则**：WBS必须包含项目100%的工作（不多不少）
- **8/80规则**：最底层工作包工期在8-80小时之间
- **工作包**：WBS最底层的可交付成果
- 体现管理活动
- 可以外包

**表现形式**：
- **列表型**：适合大项目
- **树形**：适合中小项目，直观清晰

**分解方法**：
- 按生命周期
- 按可交付成果

### 4.3 核实范围 ★★

- 是**阶段性验收**
- **与质量控制的区别**：核实范围关注"是否接受可交付成果"，质量控制关注"是否满足质量要求"
- 范围核实在前，质量控制也可在前

### 4.4 控制范围 ★★

**范围失控（蔓延）的原因**：
- 用户需求变更
- 定义不清
- 没有良好的变更控制流程

## 第五章 时间管理（进度管理）★★★

**记忆口诀：定排估估制控**（定义活动、排列顺序、估算资源、估算持续时间、制定进度、控制进度）

### 5.1 时间参数 ★★★（计算必考）

| 参数 | 含义 | 计算 |
|------|------|------|
| ES | 最早开始 | 正推法求得 |
| EF | 最早完成 | ES + 工期 |
| LS | 最晚开始 | 逆推法求得 |
| LF | 最晚完成 | 逆推法求得 |
| TF（总浮动） | 可以延迟多久不影响项目完成 | **TF = LS - ES** |
| FF（自由浮动） | 可以延迟多久不影响后续活动最早开始 | **FF = min(紧后ES) - EF** |

> **通俗理解**：TF就是"这个活动最多能拖多久，项目还不延期"；FF就是"这个活动最多能拖多久，不耽误下一个活动按最早时间开始"

### 5.2 依赖关系 ★★

- **强制依赖**：必须遵守的逻辑（先打地基后建墙）
- **外部依赖**：与外部因素有关
- **可选择的**：基于经验的最佳实践

### 5.3 排序工具 ★★

| 工具 | 代号 | 特点 |
|------|------|------|
| 前导图法（PDM） | 单代号 | 节点表示活动，**用得最多** |
| 箭线图法（ADM） | 双代号 | 箭线表示活动，可能需要虚活动 |

**PDM的四种关系**：
- FS（完成-开始）：最常用
- FF（完成-完成）
- SS（开始-开始）
- SF（开始-完成）：最少用

### 5.4 估算活动持续时间 ★★

| 方法 | 说明 |
|------|------|
| 三点估算 | 考虑最乐观、最悲观、最可能 |
| 类比估算 | 用类似项目的历史数据 |
| 参数模型 | 用数学公式 |

### 5.5 关键路径法（CPM）★★★

> **通俗理解**：项目中最长的那条路径就是关键路径，它决定了项目最短完成时间。关键路径上的活动一个都不能延误！

**关键路径特征**：
- 总浮动时间 TF = 0
- 关键路径是项目工期最长的路径
- 可能有多条关键路径

**判断步骤**：
1. 画出网络图
2. 正推法求ES/EF（取大值）
3. 逆推法求LS/LF（取小值）
4. TF = LS - ES = 0 的就是关键路径

### 5.6 PERT三点估算 ★★★（计算必考）

**公式**：

```
期望工期 t = (a + 4m + b) / 6
标准差 σ = (b - a) / 6
方差 σ² = [(b - a) / 6]²
```

- a = 最乐观时间
- m = 最可能时间  
- b = 最悲观时间

> **通俗理解**：给最可能时间4倍权重，加上最好和最差情况，除以6求平均。标准差就是"不确定性有多大"。

**完成概率**：
- 在期望工期内完成：**50%**
- ±1σ：**68.26%**
- ±2σ：**95.46%**
- ±3σ：**99.73%**

### 5.7 进度压缩 ★★★

| 方法 | 做法 | 特点 |
|------|------|------|
| **赶工** | 加资源（加人/加班） | 增加成本，只对关键路径有效 |
| **快速跟进（并行）** | 本来串行的活动并行做 | 可能增加风险，不增加成本 |

### 5.8 进度计划的分类 ★

| 类型 | 适用对象 |
|------|----------|
| 里程碑计划 | 给高层管理者看 |
| 阶段性计划 | 给中层看 |
| 详细甘特图 | 给执行团队看 |

## 第六章 成本管理 ★★★

**记忆口诀：估预控**（估算成本、制定预算、控制成本）

### 6.1 基本概念 ★★

| 概念 | 说明 |
|------|------|
| 成本基准 | 批准的按时间分配的预算 |

### 6.2 估算成本方法 ★★

- 类比估算（自上而下）
- 自下而上估算（最精确）
- 专家判断
- 参数估算
- 准备金分析

### 6.3 挣值分析（EVM）★★★（必考计算题！）

这是全书最重要的计算部分，每年必考！

#### 三个基本参数

| 参数 | 新名称 | 旧名称 | 含义 |
|------|--------|--------|------|
| **PV** | 计划值 | BCWS | 计划到此刻应该完成多少钱的工作 |
| **EV** | 挣值 | BCWP | 实际到此刻完成了多少钱的工作 |
| **AC** | 实际成本 | ACWP | 实际到此刻花了多少钱 |

> **通俗理解**：  
> PV = 计划花多少钱做多少事  
> EV = 实际做了多少事值多少钱  
> AC = 实际花了多少钱

#### 四个绩效指标 ★★★

| 指标 | 公式 | 含义 | 判断 |
|------|------|------|------|
| **CV（成本偏差）** | CV = EV - AC | 花钱是否超支 | >0 节约，<0 超支 |
| **SV（进度偏差）** | SV = EV - PV | 进度是否滞后 | >0 提前，<0 滞后 |
| **CPI（成本绩效指数）** | CPI = EV / AC | 每花1块钱产生多少价值 | >1 节约，<1 超支 |
| **SPI（进度绩效指数）** | SPI = EV / PV | 计划工作完成了百分之几 | >1 提前，<1 滞后 |

> **速记口诀**：  
> - 偏差都是 EV 打头：EV-AC，EV-PV  
> - 指数都是 EV 做分子：EV/AC，EV/PV  
> - C（成本）找AC，S（进度）找PV  
> - 大于0或大于1都是好事

#### 完工估算（EAC）★★★

| 场景 | 公式 | 适用情况 |
|------|------|----------|
| 非典型偏差 | **EAC = AC + BAC - EV** | 偏差是一次性的，未来不会再发生 |
| 典型偏差 | **EAC = AC + (BAC - EV) / CPI** | 偏差会继续，按当前效率走下去 |
| 通用 | **EAC = AC + ETC** | ETC为剩余工作估算 |

> **通俗理解**：  
> - BAC = 项目总预算  
> - EAC = 预计最终花多少钱  
> - 非典型：以前超支的就超了，以后按原计划花钱  
> - 典型：以后还是按现在这个烧钱速度

#### 完工尚需绩效指数（TCPI）★★

```
TCPI = (BAC - EV) / (BAC - AC)    基于BAC
TCPI = (BAC - EV) / (EAC - AC)    基于EAC
```

> **通俗理解**：剩余的工作需要以多高的效率完成才能不超预算。TCPI > 1说明需要比以前更高效才行。

#### 经典场景判断 ★★★

| 场景 | 含义 |
|------|------|
| AC > PV > EV | 进度落后且超支（最差情况）|
| EV > PV > AC | 进度提前且节约（最好情况）|
| EV > AC > PV | 进度提前且节约 |
| AC > EV > PV | 进度提前但超支 |
| PV > AC > EV | 进度落后且超支 |
| PV > EV > AC | 进度落后但节约 |

## 第九章 沟通管理 ★★

**记忆口诀：识规发管报**

### 9.1 沟通渠道公式 ★★★（计算必考）

```
沟通渠道数 = n(n-1) / 2
```

> **通俗理解**：n个人的团队，每两个人之间有一条沟通线，就是组合数C(n,2)。  
> 例：10个人 → 10×9/2 = 45条沟通渠道  
> 新加1人变11人 → 11×10/2 = 55条（增加了10条）

## 第十一章 风险管理 ★★★

**记忆口诀：规识定量量应监**（规划、识别、定性分析、定量分析、应对规划、监控）

### 11.1 风险概念 ★★

- **随机性**、**相对性**
- **分类方式1**：按可管理性、按可预测性、按风险来源、按影响范围、按后果
- **分类方式2**：项目风险、市场风险、技术风险

### 11.2 识别风险工具 ★★

- 图解技术：因果图
- 信息收集技术：头脑风暴、德尔菲、访谈、SWOT分析
- 输出：**风险登记册**

### 11.3 定性风险分析 ★★

- **目的**：确定风险优先级、确定风险类型
- **工具**：
  - 风险概率和影响评估
  - **概率和影响矩阵**
  - 紧迫性评估
  - 风险分类
  - 风险数据质量评估
  - 十大风险事项跟踪
  - 专家判断

### 11.4 定量风险分析 ★★

| 工具 | 说明 |
|------|------|
| **EMV（期望货币值）和决策树** | 概率×影响值 |
| 敏感性分析 | 看哪个因素影响最大 |
| 蒙特卡罗分析 | 模拟法，多次随机模拟 |

**EMV公式** ★★★：
```
EMV = 概率 × 影响值（金额）
```

> **通俗理解**：如果一个风险有30%概率发生，会损失10万，则EMV = 30% × (-10万) = -3万

### 11.5 风险应对策略 ★★★

**消极风险（威胁）应对**：

| 策略 | 含义 | 记忆 |
|------|------|------|
| **回避** | 改变计划消除风险 | 不做了 |
| **转移** | 转嫁给第三方（买保险） | 别人扛 |
| **减轻** | 降低概率或影响 | 少一点 |
| **接受** | 不采取行动 | 认了 |

**积极风险（机会）应对**：

| 策略 | 含义 |
|------|------|
| **开拓** | 确保机会实现 |
| **强大** | 增加概率或影响 |
| **分享** | 与第三方合作获益 |
| **接受** | 不主动追求但不拒绝 |

## 案例分析答题模板 ★★★

### 挣值分析题答题步骤

1. 列出已知：PV、AC、EV（或根据完成百分比算EV = 完成% × BAC）
2. 算偏差：CV = EV - AC，SV = EV - PV
3. 算指数：CPI = EV/AC，SPI = EV/PV
4. 判断：CV<0超支，SV<0落后
5. 算EAC（根据题目判断典型/非典型）
6. 给出建议措施

### 进度网络图题答题步骤

1. 画出网络图（注意依赖关系）
2. 正推求ES/EF（取大值向前推）
3. 逆推求LS/LF（取小值向后推）
4. 求总浮动TF = LS - ES
5. TF=0的路径即关键路径
6. 关键路径工期 = 项目最短工期

### 变更管理题答题模板

问题常见答法：
- 没有走正式变更流程
- 没有经过CCB审批
- 没有评估变更影响
- 没有通知相关干系人
- 变更后没有更新文档/基线

建议措施：
- 建立变更管理流程
- 所有变更需CCB审批
- 评估变更对范围/进度/成本/质量的影响
- 及时更新相关文档和基线
- 通知所有受影响的干系人
