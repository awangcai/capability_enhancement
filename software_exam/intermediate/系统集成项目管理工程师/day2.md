## 一、项目范围管理

### 1.1 范围说明书内容（必记）
- 目标
- 产品范围描述
- 需求
- **边界**（严格定义包含什么、不包含什么）
- 可交付成果
- 制约因素
- 假设条件

### 1.2 WBS（工作分解结构）★★★★★

#### 作用
- 把可交付成果分解为较小、易于管理的部分
- 为交付结果提供结构化视图

#### WBS处理过程（5步，必记）
1. **识别**和分析可交付成果及相关工作（必须且只能包含100%的工作）
2. **确认**WBS的结构和编排方法
3. **自上而下**逐层细化分解（3-6层为宜）
4. 制定并分配**编码**
5. **核实**分解程度是否恰当

#### WBS编排方法

| 方法 | 特点 | 适用 |
|------|------|------|
| 树形 | 层次清晰 | 中小型项目 |
| 列表型 | 反应所有要素，直观性差 | 大型、复合型项目 |

#### WBS标准结构（至少包含）
```
项目
├── 需求（调研、分析、确认、文档）
├── 设计（数据库、类库、接口、功能、文档）
├── 开发（数据库、界面、接口、功能、文档）
├── 测试（单元、集成、系统、验收、报告）
├── 管理（计划、监控）
└── 培训
```

#### WBS重要概念

| 术语 | 定义 |
|------|------|
| 工作包 | WBS最底层可交付成果，8-80小时内完成或逻辑上不可再分 |
| 活动 | 工作包再细分的最基本单元 |
| 控制账户 | 管理控制点，整合范围/预算/成本/进度，与挣值比较 |
| WBS词典 | 给每个部分账户编码标识符 |

#### 案例题：WBS存在什么不合理（答题模板）
- 分解未包括XX工作（如项目管理、培训）
- 测试分解不够完整，还应包括XX（单元/集成/系统测试）
- 相同层次工作单元应有相同性质，XX应分解到XX部分
- 缺少WBS词典/编码

#### WBS的输入与输出

| 类别 | 内容 |
|------|------|
| 输入 | 范围管理计划、项目范围说明书、需求文件 |
| 工具与技术 | 分解、专家判断 |
| 输出 | 范围基准、项目文件更新 |

### 1.3 确认范围 vs 质量控制

| | 确认范围 | 质量控制 |
|--|---------|---------|
| 关注点 | 可交付成果的**验收** | 可交付成果的**正确性、质量** |
| 时间 | 质量控制之后 | 确认范围之前 |

## 二、项目进度管理

### 2.1 活动排列方法

#### 前导图法（PDM）= 单代号网络图
- 节点表示活动
- 箭头表示依赖关系
- 每个节点含六个时间参数（六时图）：

```
┌────────────────────┐
│ ES │ 工期 │ EF    │
├────────────────────┤
│ LS │ 浮动 │ LF    │
└────────────────────┘
```

- ES：最早开始时间
- EF：最早结束时间 = ES + 工期
- LS：最晚开始时间
- LF：最晚结束时间
- 总浮动 = LS - ES = LF - EF

#### 箭线图法（ADM）= 双代号网络图
- 箭头表示活动（实活动用实线，虚活动用虚线）
- 节点表示活动的开始和结束
- 节点序号沿箭头方向递增
- **虚活动**：不消耗时间和资源，只表示逻辑关系

### 2.2 关键路径法（CPM）

#### 核心概念
- **关键路径**：从开始到结束，耗时最长的路径
- **关键路径长度** = 项目最短工期
- 关键路径上活动的总浮动时间 = 0
- 一个项目可能有**多条**关键路径

#### 计算步骤
1. **正推法**（求ES/EF）：从左到右，取前驱活动EF的**最大值**作为后续活动的ES
2. **逆推法**（求LS/LF）：从右到左，取后继活动LS的**最小值**作为前置活动的LF
3. 计算总浮动 = LS - ES = LF - EF

#### 浮动时间

| 类型 | 定义 | 计算方法 |
|------|------|---------|
| 总浮动（总时差） | 不延误项目完工时间可推迟的时间 | LS - ES 或 LF - EF |
| 自由浮动（自由时差） | 不延误紧后活动可推迟的时间 | 紧后活动ES - 本活动EF |

### 2.3 活动依赖关系

| 类型 | 说明 |
|------|------|
| 强制性依赖 | 法律法规、合同、客观限制 |
| 选择性依赖 | 最佳实践或项目特殊性质（快速跟进时可审查） |
| 内部依赖 | 项目内部活动间 |
| 外部依赖 | 与项目外部活动间 |

### 2.4 进度调整工具

| 技术 | 特点 |
|------|------|
| 关键链法 | 考虑资源限制和时间限制 |
| 资源平滑 | 不改变关键路径和总工期 |
| 资源平衡 | 可能延长关键路径和总工期 |
| 赶工 | 增加资源压缩进度（增加成本） |
| 快速跟进 | 并行施工（增加风险） |

> **考点区分**：
> - 资源平滑 → 不改变工期
> - 资源平衡 → 可能延长工期

### 2.5 分解结构区分（常考选择题）

| 缩写 | 全称 | 分解对象 |
|------|------|---------|
| WBS | 工作分解结构 | 项目工作 |
| RBS | 资源分解结构 | 项目资源 |
| OBS | 组织分解结构 | 人力资源/组织层级 |
| RAM | 责任分配矩阵 | 工作与人员对应关系 |

## 三、双代号时标网络图（案例题常考）

### 3.1 读图要点
- 水平轴 = 时间
- 实线水平长度 = 活动持续时间
- 波浪线（虚线）长度 = 自由时差

### 3.2 总时差计算
在时标网络图中，某活动的总时差 = 该活动之后所有路径中波浪线总长度的**最小值**

### 3.3 常见题型

**Q：某活动延期X天，总工期延迟多少？**
- 在关键路径上：延迟X天
- 不在关键路径上：延迟 = max(0, X - 总浮动时间)

**Q：某活动最多可延期多少天不影响总工期？**
- 在关键路径上：0天
- 不在关键路径上：等于该活动的总浮动时间

## 练习题

1. WBS最底层可交付成果称为（）？
   A. 活动 B. 工作包 C. 控制账户 D. 里程碑
   **答案：B**

2. 某网络图中，A→B→D路径总工期15天，A→C→D路径总工期12天，则项目最短工期为（）天。
   A. 12 B. 15 C. 27 D. 3
   **答案：B**（关键路径=最长路径）

3. 某活动ES=5，EF=10，LS=8，则总浮动时间为（）天。
   A. 2 B. 3 C. 5 D. 8
   **答案：B**（LS-ES=8-5=3）

4. 确保资源使用不超过最大可用量，可能延长关键路径的是（）。
   A. 资源平滑 B. 资源平衡 C. 赶工 D. 快速跟进
   **答案：B**
