## 一、挣值分析 ★★★★★（每年必考，上午+下午都考）

### 1.1 挣值分析到底是什么？

想象你是包工头，接了个100万的工程，计划10个月干完。

干到第5个月，老板问："项目怎么样了？"

你需要回答三个问题：
- 按计划到现在**应该干了多少活**？→ 这就是**PV**
- 实际上你们**干了多少活**？→ 这就是**EV**  
- 实际上你们**花了多少钱**？→ 这就是**AC**

然后用这三个数比一比，就知道项目是好是坏了。

### 1.2 三个基本值——用具体例子理解

**场景**：项目总预算BAC=100万，计划10个月完工。现在是第5个月末。

| 指标 | 计算 | 含义 |
|------|------|------|
| **PV=50万** | 100万×50%（过了一半时间） | 按计划到现在应该做了50万的活 |
| **EV=40万** | 100万×40%（实际只做了40%） | 实际上只做了40万的活（慢了） |
| **AC=60万** | 实际花了60万（看账本） | 花了60万却只做了40万的活（贵了） |

> **核心理解**：PV和EV都是"用预算金额来衡量工作量"——不是看实际花了多少，而是看"做的这些活本来值多少钱"

### 1.3 绩效指数——一个比值判好坏

**CPI = EV/AC = 40/60 = 0.67**

> 花了60万，但只做了值40万的工作。每花1块钱只产出了0.67块钱的价值。
> **小于1 = 亏了 = 成本超支**

**SPI = EV/PV = 40/50 = 0.8**

> 计划做50万的活，实际只做了40万的活。进度只达到了计划的80%。
> **小于1 = 慢了 = 进度滞后**

### 1.4 偏差——具体差了多少

**CV = EV-AC = 40-60 = -20万**
> 做了40万的活花了60万，多花了20万。**负数=超支**

**SV = EV-PV = 40-50 = -10万**
> 该做50万的活实际做了40万，少做了10万的工作量。**负数=滞后**

### 1.5 预测——项目最终会怎样？

这是最重要也最容易错的部分。关键是**先判断偏差类型**：

**典型偏差**（后面也会这么差）：
> 就像学生平时考试一直60分，期末也不会突然考90分。
> 公式用除法：**EAC = BAC/CPI = 100/0.67 = 149万**
> 意思是：按这个烧钱速度，最终要花149万才能做完。

**非典型偏差**（只是偶尔犯一次错）：
> 就像学生平时考90分，这次偶然考了60分，下次还会恢复90。
> 公式用加减法：**EAC = AC+BAC-EV = 60+100-40 = 120万**
> 意思是：已经花了60万+剩余工作还要60万(100-40)=总共120万。

**怎么判断用哪个？看题目关键词**：
- "按当前趋势""效率保持不变""无有效纠正措施" → **典型**（用除法）
- "偏差是偶然的""已找到原因""不会再发生" → **非典型**（用加减法）
- 题目没明确说 → **默认按典型**

### 1.6 VAC——最终盈亏

**VAC = BAC - EAC**
> 预算100万，预计要花149万，那就亏了49万。
> VAC = 100-149 = -49万（负数=亏损/超支）

## 二、关键路径法 ★★★★★（每年必考）

### 2.1 关键路径是什么？

想象你要办一场婚礼，有这些事要做：
- 订酒店(2周) → 装饰酒店(1周) → 婚礼当天
- 订婚纱(3周) → 试穿修改(1周) → 婚礼当天  
- 发请柬(1周) → 统计人数(1周) → 确定桌数(0.5周) → 婚礼当天

哪条线最长？**订婚纱→试穿修改 = 4周**

这条最长的线就是**关键路径**——整个项目最快也得4周才能完成。

> **关键路径 = 从头到尾最长的那条路 = 项目最短工期**
> 关键路径上任何一个环节延误，整个项目都会延误。

### 2.2 六时图怎么算？

每个活动有6个时间参数（所以叫六时图）：
```
┌──────────────────────┐
│  ES  │  工期  │  EF  │    ES=最早开始 EF=最早结束
├──────────────────────┤
│  LS  │  浮动  │  LF  │    LS=最晚开始 LF=最晚结束
└──────────────────────┘
```

**正推（从前往后）求ES和EF**：
> 问："这件事最早什么时候能开始？"
> 答："得等前面所有事都做完才能开始"
> 如果有多个前置任务 → 等最慢那个做完 → **取最大值**
> EF = ES + 工期

**逆推（从后往前）求LS和LF**：
> 问："这件事最晚什么时候必须开始？"
> 答："得保证后面所有事都不耽误"
> 如果有多个后续任务 → 照顾最着急那个 → **取最小值**
> LS = LF - 工期

### 2.3 浮动时间——能拖多久？

**总浮动时间 = LS - ES**（或 LF - EF，结果一样）
> 意思是：这件事最多能推迟多少天，还不影响整个项目的完工日期。
> 关键路径上的活动：总浮动 = 0（一天都不能拖！）

**自由浮动时间 = 紧后活动的ES - 本活动的EF**
> 意思是：这件事最多能推迟多少天，还不影响下一件事按时开始。
> 自由浮动 ≤ 总浮动（不耽误下一件事，肯定也不耽误整个项目）

### 2.4 活动延误问题怎么解？

**问：活动X延误了Y天，总工期延迟多少？**

方法：
1. 先看活动X在不在关键路径上
2. 如果在：延迟Y天（关键路径上一天都不能拖）
3. 如果不在：延迟 = max(0, Y - 总浮动时间)
   - Y ≤ 总浮动 → 不延迟
   - Y > 总浮动 → 延迟 = Y - 总浮动

### 2.5 工期压缩怎么做？

1. 找出当前关键路径
2. 看关键路径上哪些活动能压缩
3. **优先压缩"每天增加费用最小"的活动**
4. 压缩后检查：有没有产生新的关键路径？
5. 如果有新关键路径，两条都要同时压缩
6. 计算净成本 = 压缩增加的费用 - 节省的间接费用×压缩天数

## 三、WBS工作分解结构 ★★★★★（高频案例题）

### 3.1 WBS是什么？

就是把一个大项目**拆成小块**，像剥洋葱一样一层层分解：

```
盖一栋楼（大项目）
├── 地基工程（大块）
│   ├── 挖坑（小块）
│   ├── 打桩（小块）
│   └── 浇筑（小块）
├── 主体工程
│   ├── 搭框架
│   └── 砌墙
├── 装修工程
│   ├── 水电
│   └── 精装修
└── 验收
```

### 3.2 两个核心规则

**100%规则**：WBS必须覆盖项目100%的工作
> 不能多：不属于项目范围的不能放进来
> 不能少：属于项目范围的一项都不能漏

**8-80规则**：最底层工作包应在8-80小时内完成
> 太小（<8h）：管理成本大于收益（分得太细）
> 太大（>80h）：不好估算和控制（分得太粗）

### 3.3 案例题中WBS最常考的3个错误

| 错误 | 为什么是错的 | 正确做法 |
|------|-------------|---------|
| 整个WBS没有"项目管理"分支 | 管理工作也是工作的一部分 | 加上"项目管理"（含计划、监控） |
| 整个WBS没有"培训"分支 | 系统上线前要培训用户 | 加上"培训" |
| 测试只写了"测试"一项 | 测试有多个阶段 | 细分为单元测试/集成测试/系统测试/验收测试 |

## 四、变更管理 ★★★★★（高频案例题）

### 4.1 为什么变更管理重要？

没有变更管理会发生什么？
- 客户今天说"加个功能"，明天说"改个颜色"，后天说"全部重做" → **项目永远做不完**
- 开发人员偷偷改代码，改出bug没人知道 → **产品质量失控**
- 改了东西没更新文档，后面的人不知道改了什么 → **团队混乱**

### 4.2 核心要记住的3件事

**1. CCB是什么？**
> CCB = Change Control Board = 变更控制委员会
> - 不是常设机构（不是每天开会，需要审批变更时才召集）
> - 成员通常包括：项目发起人、PM、技术负责人、客户代表
> - **只负责审批**（批准/拒绝），不负责执行变更

**2. 谁能做什么？**
```
客户：提出需求变更（只能"说"要改）
项目经理：评估影响（分析改了会怎样）
CCB：审批是否执行（拍板决定改不改）
开发人员：执行变更（CCB批准后才能动手）
```

**3. 正确的变更流程**
```
提出(任何人) → 记录(PM) → 评估影响(PM+团队) → CCB审批 
→ 批准后执行 → 更新文档 → 纳入配置管理 → 通知干系人
```

### 4.3 案例题中最典型的错误场景

> "客户直接找开发人员说要修改功能，开发人员觉得不难就直接改了"

这一句话至少违反了5条原则：
1. ❌ 变更未经项目经理知晓
2. ❌ 变更未记录
3. ❌ 变更未经影响分析
4. ❌ 变更未经CCB审批
5. ❌ 变更后文档未更新

## 五、配置管理 ★★★★★（高频选择+案例）

### 5.1 配置管理是什么？

简单说就是**版本管理**——管好项目中产生的所有文件的版本。

为什么需要？想象没有配置管理：
- 小王改了代码忘告诉别人，小李还在用旧版本
- 上线时不知道哪个版本是对的
- 出了bug查不到是谁、什么时候改了什么

### 5.2 六个活动详解

| 活动 | 像什么 | 具体做什么 |
|------|--------|-----------|
| **计划** | 制定图书馆借阅规则 | 定好怎么管版本的规矩 |
| **标识** | 给每本书贴编号 | 给每个要管的东西编号、打标签 |
| **控制** | 借书要登记审批 | 要改东西必须走审批流程 |
| **状态记录** | 记录谁借了什么书 | 记录每次变化（谁改了什么、什么时候） |
| **审计** | 查查有没有人偷书 | 检查有没有人违规操作 |
| **发布** | 新书上架 | 正式发布某个版本给用户使用 |

### 5.3 三种库详解

| 库 | 别名 | 像什么 | 控制方式 | 谁用 |
|----|------|--------|---------|------|
| **开发库** | 动态库/工作库 | 你电脑上的草稿 | 自己随便改 | 开发人员 |
| **受控库** | 主库 | 公司共享盘 | 改要走审批 | 整个项目团队 |
| **产品库** | 静态库/发行库 | 发给客户的成品 | 只读不能改 | 客户/运维 |

> **流转方向**：开发库 → (审批) → 受控库 → (发布) → 产品库

### 5.4 配置审计的两种类型

| 类型 | 检查什么 | 用一句话概括 |
|------|---------|-------------|
| **功能配置审计** | 做出来的东西和要求的**一致**吗？ | 功能对不对、性能达不达标 |
| **物理配置审计** | 该交的东西**全**吗？ | 文件有没有漏、内容齐不齐 |

> 记忆：功能=**一致**性（对不对），物理=**完整**性（全不全）

## 六、风险应对策略 ★★★★★（高频选择+案例）

### 6.1 四种策略的通俗理解

| 策略 | 生活类比 | 本质 | 举例 |
|------|---------|------|------|
| **规避** | 怕出车祸就不开车 | 让风险**不可能**发生 | 取消使用新技术、换成熟方案 |
| **减轻** | 开车系安全带+买好刹车 | **降低**概率或影响 | 多做测试、培训人员、增加备份 |
| **转移** | 买保险让保险公司赔 | 让**别人**承担后果 | 买保险、外包给专业公司 |
| **接受** | 知道可能堵车但还是出门 | **认了**，做好应急准备 | 制定应急预案 |

### 6.2 怎么判断该用哪个策略？

```
影响大 + 概率高 → 规避（直接不做这个有风险的事）
影响大 + 概率低 → 减轻或转移
影响小 → 接受（做个预案就行）
```

### 6.3 考试中怎么判断是哪个策略？

| 看到这些描述 | 选择 |
|-------------|------|
| "取消""不做""完全消除" | **规避** |
| "多做测试""提前培训""增加人员" | **减轻** |
| "买保险""外包""合同约定由对方承担" | **转移** |
| "制定应急预案""准备好了但不主动避免" | **接受** |

## 七、质量控制七工具 ★★★★（高频选择题）

### 7.1 七个工具各是什么？

| 工具 | 长什么样 | 用来干什么 | 考试关键词 |
|------|---------|-----------|-----------|
| **因果图**(鱼骨图) | 像鱼骨头 | 找出**所有**可能原因 | "所有原因""鱼骨" |
| **帕累托图** | 条形图+折线 | 找出**少数主要**原因 | "主要原因""二八法则" |
| **直方图** | 竖条组成的柱状图 | 看数据**分布**情况 | "集中趋势""分散程度" |
| **控制图** | 折线+上下两条横线 | 看过程是否**在范围内** | "控制界限""上下限" |
| **散点图** | 平面上很多点 | 看**两个变量**有无关系 | "两变量""相关性" |
| **流程图** | 方框+箭头 | 了解做事**步骤** | "过程""步骤" |
| **核查表** | 表格打勾 | **收集**质量数据 | "收集数据""记录" |

### 7.2 最常考的区分题

> **垂直条形图找质量问题——是帕累托还是直方图？**

**答**：看关键词！
- 说"找出**主要原因**""**二八法则**""**关键少数**" → 帕累托图
- 说"看**分布**""**集中趋势**""**分散程度**" → 直方图

## 八、招投标关键数字 ★★★★（高频选择题）

### 8.1 故事版记忆

> 小明公司要做一个IT项目，需要招标找供应商。
>
> 第一步【招标】：
> 小明在网上发了招标公告，**公示5天**以上让大家知道。
> 有好多公司来报名，经过资格预审，至少**3家**通过才算数（不够3家要重新招标）。
> 投标的公司要交保证金，但不能超过项目估价的**2%**，而且最多不能超过**80万**。
>
> 第二步【评标】：
> 找了一个评标委员会来打分。常规招标要**5个人以上且是单数**（竞争性谈判至少3人）。
> 这些评标人里，技术和经济方面的专家要占**三分之二**以上。
> 评标结果在**3天内**公布，然后**公示3天**。有人不服可以提异议，**3天内**要答复。
>
> 第三步【中标】：
> 选出不超过**3个**候选人，排好名次。
> 中标的公司要在**30天内**签合同。
> 没中标的公司**5天内**退还保证金。
> 中标公司要交**10%**以内的履约保证金。

### 8.2 数字速记表

| 事项 | 数字 | 记忆方式 |
|------|------|---------|
| 公示期 | ≥5日 | "5天公告" |
| 预审通过 | ≥3家 | "至少3家竞争" |
| 投标保证金 | ≤2%且≤80万 | "2%封顶80万" |
| 评标委(常规) | ≥5人单数 | "5人以上单数" |
| 评标委(竞争) | ≥3人单数 | "3人以上单数" |
| 专家比例 | ≥2/3 | "三分之二专家" |
| 评标公布 | ≤3日 | "3天出结果" |
| 公示时间 | ≥3日 | "公示3天" |
| 异议答复 | 3日内 | "3天回复" |
| 候选人数 | ≤3人 | "最多3人" |
| 签合同 | 30日内 | "30天签约" |
| 退保证金 | 5日内 | "5天退钱" |
| 履约保证金 | ≤10% | "10%履约" |

## 九、三点估算PERT ★★★★★（高频计算题）

### 9.1 为什么不直接估一个数？

因为一个数太不准了。给三个数（最快/最可能/最慢），然后加权平均更靠谱。

### 9.2 公式的直觉理解

**Te = (O + 4M + P) / 6**

为什么M的权重是4？因为"最可能"出现的概率最大，所以给最大的权重。
- O(乐观)权重1 + M(最可能)权重4 + P(悲观)权重1 = 总权重6
- 所以除以6

**σ = (P - O) / 6**

标准差反映"不确定性有多大"。悲观和乐观差距越大，不确定性越高。

### 9.3 正态分布怎么用？

| 范围 | 概率 | 含义 |
|------|------|------|
| Te ± 1σ | 68% | 大概率在这个范围内 |
| Te ± 2σ | 95% | 几乎确定在这个范围内 |
| Te ± 3σ | 99.7% | 极其确定 |

**快速查表**（考试常用）：
- 目标时间 = Te → 概率 50%
- 目标时间 = Te + 1σ → 概率 84%（50%+34%）
- 目标时间 = Te + 2σ → 概率 97.5%（50%+47.5%）
- 目标时间 = Te - 1σ → 概率 16%（50%-34%）

### 9.4 完整例题

某活动：乐观O=4天，最可能M=7天，悲观P=16天

```
Te = (4 + 4×7 + 16) / 6 = (4+28+16)/6 = 48/6 = 8天
σ = (16-4)/6 = 12/6 = 2天
```

问：在10天内完成的概率？
```
10天 = Te + 1σ = 8 + 2 = 10
概率 = 50% + 34% = 84%
```

## 十、沟通渠道公式 ★★★★（每年至少1题）

### 10.1 公式

```
沟通渠道数 = n(n-1)/2
```

### 10.2 为什么是这个公式？

n个人，每两个人之间有一条沟通线路。就是"从n个人中选2个"的组合数。

### 10.3 常见陷阱
