### 2.1 挣值分析公式 ★★★★★

> **什么是挣值分析？**
> 项目做到一半时，老板问"项目怎么样了"，你需要用数据回答：花了多少钱？做了多少事？和计划比怎么样？
> 挣值分析就是用三个数字精确回答这些问题的方法。

#### 三个基本值（必须先理解这三个）

| 缩写 | 全称 | 中文 | 通俗理解 | 怎么算 |
|------|------|------|---------|--------|
| **PV** | Planned Value | 计划值 | 按计划，到今天**应该完成**多少工作（用钱衡量） | 计划完成百分比 × 总预算 |
| **EV** | Earned Value | 挣值 | 到今天**实际完成了**多少工作（用钱衡量） | 实际完成百分比 × 总预算 |
| **AC** | Actual Cost | 实际成本 | 到今天**实际花了**多少钱 | 直接看账本（题目给出） |

> **生活举例**：你计划10天花1000元装修一个房间
> - 第5天时：PV = 500元（计划到第5天应完成50%的工作）
> - 第5天时你实际只完成了30%：EV = 300元
> - 第5天你实际已经花了400元：AC = 400元
> - 结论：活干少了（EV<PV进度慢），钱花多了（AC>EV成本超）

#### 绩效指数（判断好坏的指标）

| 公式 | 全称 | 含义 | 怎么理解 | 判断标准 |
|------|------|------|---------|---------|
| **CPI = EV/AC** | Cost Performance Index 成本绩效指数 | 每花1块钱创造了多少价值 | 花了AC的钱，但只做了EV的工作。比值<1说明花的比做的多→亏了 | >1节约 <1超支 =1刚好 |
| **SPI = EV/PV** | Schedule Performance Index 进度绩效指数 | 实际速度是计划速度的多少倍 | 计划做PV的工作，实际做了EV。比值<1说明做的比计划少→慢了 | >1提前 <1滞后 =1正常 |

> **记忆技巧**：CPI和SPI公式中，**EV永远在分子**（上面），因为EV是"实际产出"，是衡量一切的核心

#### 偏差（超了多少/差了多少）

| 公式 | 全称 | 含义 | 怎么理解 | 判断标准 |
|------|------|------|---------|---------|
| **CV = EV - AC** | Cost Variance 成本偏差 | 做的工作值多少钱 vs 实际花了多少钱 | 做了EV的活但花了AC的钱，差值就是赚/亏多少 | >0节约 <0超支 |
| **SV = EV - PV** | Schedule Variance 进度偏差 | 实际做了多少 vs 计划做多少 | 实际做了EV但计划应做PV，差值就是快/慢多少 | >0提前 <0滞后 |

> **记忆技巧**：偏差公式中，**EV永远在前面**（被减数）

#### 预测值（预估项目完工时的情况）

| 缩写 | 全称 | 含义 | 通俗理解 |
|------|------|------|---------|
| **BAC** | Budget at Completion 完工预算 | 项目总预算 | 一开始计划花多少钱（题目直接给） |
| **EAC** | Estimate at Completion 完工估算 | 预计完工时总共要花多少钱 | 按现在情况推算，最终花多少 |
| **ETC** | Estimate to Complete 完工尚需估算 | 从现在起还要花多少钱 | 剩余工作还需要多少钱 |
| **VAC** | Variance at Completion 完工偏差 | 完工时预算剩余/超支多少 | 最终是赚还是亏 |

#### 两种偏差情况（考试必须先判断！）

| 类型 | 含义 | 判断依据 | 公式 |
|------|------|---------|------|
| **典型偏差** | 问题会一直持续下去，后面也会按这个效率干活 | 题目说"按当前趋势""效率不变""无有效措施" | EAC = BAC/CPI |
| **非典型偏差** | 问题是偶然的，后面不会再出现 | 题目说"偶然""已纠正""不会再发生" | EAC = AC + BAC - EV |

> **理解方式**：
> - 典型偏差像是"你跑步体力不行，后面也会这么慢" → 用效率(CPI)来推算总时间
> - 非典型偏差像是"你停下来系了次鞋带，后面不会再停" → 已花的+剩余工作原价

**完整公式汇总**：
```
┌─────────────────────────────────────────────────────────┐
│  基本值：PV(计划做多少) EV(实际做多少) AC(实际花多少)      │
│  BAC = 项目总预算                                        │
│                                                          │
│  绩效指数（除法，EV在上）：                                │
│    CPI = EV/AC  →  >1省钱  <1超支                        │
│    SPI = EV/PV  →  >1快了  <1慢了                        │
│                                                          │
│  偏差（减法，EV在前）：                                    │
│    CV = EV-AC   →  >0省钱  <0超支                        │
│    SV = EV-PV   →  >0快了  <0慢了                        │
│                                                          │
│  预测（先判断典型/非典型！）：                              │
│    典型：  EAC = BAC/CPI     ETC = (BAC-EV)/CPI          │
│    非典型：EAC = AC+BAC-EV   ETC = BAC-EV                │
│    完工偏差：VAC = BAC-EAC（正=盈利，负=亏损）              │
└─────────────────────────────────────────────────────────┘
```

### 2.2 三点估算PERT ★★★★★

> **什么是三点估算？**
> 估计一件事要多久时，给三个时间：最乐观、最可能、最悲观，然后用加权公式算出"期望时间"。
> "最可能"的权重最大（×4），因为它发生的概率最高。

| 符号 | 含义 | 公式 | 通俗理解 |
|------|------|------|---------|
| O | Optimistic 乐观时间 | - | 一切顺利最快要多久 |
| M | Most likely 最可能时间 | - | 正常情况下要多久 |
| P | Pessimistic 悲观时间 | - | 遇到困难最慢要多久 |
| Te | 期望时间 | **(O+4M+P)/6** | 综合考虑后最可能的完成时间 |
| σ | 标准差 | **(P-O)/6** | 不确定性有多大（数值越大越不确定） |

> **为什么除以6？** 因为权重是1+4+1=6（乐观1份，最可能4份，悲观1份）

**正态分布概率**（用于回答"在XX天内完成的概率"）：
```
期望时间 ± 1个标准差 → 覆盖68%的概率
期望时间 ± 2个标准差 → 覆盖95%的概率  
期望时间 ± 3个标准差 → 覆盖99.7%的概率
```

> **举例**：Te=10天，σ=2天
> - 在12天(10+2)内完成的概率 = 50% + 34% = **84%**
> - 在8天(10-2)内完成的概率 = 50% - 34% = **16%**
> - 在14天(10+4)内完成的概率 = 50% + 47.5% = **97.5%**

### 2.3 网络图计算 ★★★★★

> **什么是网络图？**
> 把项目所有活动画成一张图，标明先后顺序和每个活动要多久。用来算出"项目最快多久能做完"和"哪些活动不能拖延"。

| 术语 | 全称 | 含义 | 通俗理解 |
|------|------|------|---------|
| **ES** | Earliest Start | 最早开始时间 | 这件事最早什么时候能开始做 |
| **EF** | Earliest Finish | 最早结束时间 | = ES + 工期（最早开始+做多久=最早做完） |
| **LS** | Latest Start | 最晚开始时间 | 这件事最晚什么时候必须开始（再晚整个项目就延误） |
| **LF** | Latest Finish | 最晚结束时间 | 这件事最晚什么时候必须做完 |
| **总浮动** | Total Float | 总时差 | 这件事最多能拖多久，还不影响整个项目完工 |
| **自由浮动** | Free Float | 自由时差 | 这件事最多能拖多久，还不影响下一件事开始 |
| **关键路径** | Critical Path | - | 从开始到结束最长的那条路=项目最短工期 |

**计算规则**：
```
正推（从前往后算ES/EF）：
  一件事有多个前提条件 → 等所有前提都做完才能开始 → 取最大值
  
逆推（从后往前算LS/LF）：
  一件事后面有多个任务依赖它 → 保证所有后续不延误 → 取最小值

总浮动 = LS - ES = LF - EF
自由浮动 = 紧后活动的ES - 本活动的EF
关键路径上的活动：总浮动 = 0（一天都不能拖）
```

> **理解方式**：
> - 正推像是问"最早什么时候能开始" → 必须等前面的都做完 → 等最慢的那个 → 取最大
> - 逆推像是问"最晚什么时候必须开始" → 要保证后面最急的不耽误 → 照顾最着急的 → 取最小

### 2.4 沟通渠道 ★★★★

> **什么是沟通渠道？**
> 一个团队里每两个人之间可以直接沟通，渠道数就是"任选2人"的组合数。

```
沟通渠道 = n(n-1)/2

n = 团队总人数（包括项目经理自己！）
```

> **举例**：5个人的团队，渠道 = 5×4/2 = 10条
> **注意**：如果说"项目经理带领5名成员"，n=6不是5

### 2.5 预算结构 ★★★★

```
项目总预算 = 成本基准 + 管理储备

成本基准 = 各活动预算之和 + 应急储备
```

| 概念 | 是什么 | 用于什么 | 谁能动用 |
|------|--------|---------|---------|
| **应急储备** | 为已识别的风险准备的钱 | 应对"知道可能出问题"的情况 | 项目经理（包含在基准内） |
| **管理储备** | 为未知风险准备的钱 | 应对"完全没想到的"的情况 | 高层批准才能用（不在基准内） |

> **关键考点**：
> - 动用应急储备 → **不改变**成本基准（因为它本来就在基准里）
> - 动用管理储备 → **改变**成本基准（因为它原本不在基准里，用了就变成基准的一部分）

| 配置三库 | **动态开发/主库受控/静态产品** | 开发库(动态)→受控库(主库)→产品库(静态) | 开发库=你自己电脑上(随便改)；受控库=公司服务器(改要审批)；产品库=发给客户的(只读存档) | ★★★★★ |
| 干系人四过程 | **识计管控** | 识别→编制计划→管理参与→监控参与 | 干系人管理：先搞清谁是干系人→定管理计划→拉他们参与→持续盯着他们的态度变化 | ★★★★ |
| 冲突解决 | **合妥强存退** | 合作、妥协、强制、求同存异、撤退 | 合作=找双赢方案(最佳)；妥协=各让一步(各不满意)；强制=我说了算(紧急用)；求同存异=搁置争议；撤退=先不管了(冷静) | ★★★★ |
| 信息化6要素 | **法网应资技人** | 法规标准、信息网络、信息技术应用、信息资源、信息技术和产业、信息化人才 | 法规=根本保障；网络=基础设施；应用=龙头；资源=关键；技术=基础；人才=根本。记地位关键词！ | ★★★ |
| 大数据5V | **量速多值真** | Volume(大量)、Velocity(高速)、Variety(多样)、Value(低价值密度)、Veracity(真实性) | 大数据特点：数据量大+产生速度快+种类多+有用信息占比低+真假难辨 | ★★★ |
| 安全要素 | **保完可** | 保密性、完整性、可用性 | 保密=不泄露给没权限的人；完整=不被篡改；可用=需要用时能正常访问。至少记这3个 | ★★★ |

### 3.4 关键记忆句

| 场景 | 记忆句 | 详细理解 | 重要度 |
|------|--------|---------|--------|
| 挣值核心 | **EV永远是主角，除法看指数减法看偏差** | 所有挣值公式中EV都在分子或被减数位置。CPI/SPI是除法（绩效指数），CV/SV是减法（偏差） | ★★★★★ |
| 典型vs非典型 | **典型除CPI，非典型直接减** | 典型偏差EAC=BAC/CPI（用效率推算）；非典型EAC=AC+BAC-EV（已花的+剩余原价） | ★★★★★ |
| 章程发起 | **发起人发起，经理参与** | 项目章程必须由发起人或高层发布，项目经理只能参与起草不能自己发起 | ★★★★ |
| 变更权限 | **客户只能提，经理只能评，CCB才能批** | 客户=提需求的人；PM=评估影响的人；CCB=拍板决定的人。三者权限不能混 | ★★★★★ |
| 配置库 | **动态随便改，主库要审批，静态已发布** | 开发库=个人工作区(想改就改)；受控库=需要走流程才能改；产品库=已发布给客户的存档 | ★★★★ |
| 工作包 | **8到80不可再分是工作包** | WBS最底层可交付成果就是工作包，判断标准：8-80小时能完成，或逻辑上不可再分 | ★★★★ |
| 资源优化 | **滑不变，衡可延** | 资源平滑=不改变项目总工期；资源平衡=可能延长项目总工期。平滑温和，平衡激进 | ★★★★ |
| 功能vs物理审计 | **功能审一致，物理审完整** | 功能审计=检查做出来的和要求一致吗(功能对不对)；物理审计=检查该交的东西全不全(有没有漏) | ★★★★ |

### 3.5 考场应急策略

| 场景 | 策略 | 原理解释 | 重要度 |
|------|------|---------|--------|
| 选择题有"更新"字样 | 选输出 | "XX更新"一定是某个过程产生的结果（输出），不可能是输入 | ★★★★ |
| 判断题不确定 | 优先选对 | 统计上"对"的概率略高于"错" | ★★★ |

| 案例给建议不知道写啥 | **编计划做评审走变更搞培训多沟通** | 和上面对应，每个"没有"的对策就是"做起来" | ★★★★★ |

## 第四部分：案例分析答题技巧概要

---

### 4.1 什么是案例分析题？

> 给你一段项目管理的故事（2-3段文字），描述了一个项目从开始到出问题的过程。
> 然后问你：存在什么问题？应该怎么改进？有时还有计算题。

### 4.2 答题五原则 ★★★★★

| 原则 | 解释 | 为什么 |
|------|------|--------|
| **多写要点** | 宁愿多写3条也别少写1条 | 阅卷是"踩点给分"，多写不扣分，少写就丢分 |
| **分点编号** | 用1、2、3、4清晰列出 | 阅卷老师快速找到得分点 |
| **先总后分** | 先给结论再展开 | 即使展开部分写得不好，结论也能得分 |
| **不留空白** | 完全不会也要写相关内容 | 写了可能得1-2分，空着必然0分 |
| **计算写全** | 公式→代入数据→结果→单位→结论 | 每一步都有可能是得分点 |

### 4.3 "找问题"万能五步法 ★★★★★

> 拿到案例题，按这5步扫描文本，基本能找出所有问题：

| 步骤 | 关注点 | 常见问题 | 理解 |
|------|--------|---------|------|
| **Step1 看身份** | PM是谁？什么背景？ | 技术转管理缺培训、身兼数职 | 很多问题根源是PM不专业 |
| **Step2 看过程** | 计划怎么编的？ | 一个人编、没有评审就执行 | 计划是项目的基础，必须全员参与+评审 |
| **Step3 看变更** | 需求改了怎么处理的？ | 没走流程、没有CCB、没更新文档 | 变更不控制=项目失控 |
| **Step4 看监控** | 项目执行时有没有人盯着？ | 没监控、发现偏差没纠偏 | 不监控就像开车不看仪表盘 |
| **Step5 看沟通** | 各方有没有充分沟通？ | 干系人没参与、信息不对称 | 很多矛盾源于沟通不足 |

### 4.4 万能保底8条 ★★★★★

> 这8条几乎适用于任何管理类案例题，实在不知道写什么就写这些：

| 编号 | 答案 | 为什么这是问题 |
|------|------|---------------|
| 1 | 应编制XX管理计划 | 没有计划就没有执行依据 |
| 2 | 应组织全体干系人参与评审 | 一个人说了不算，要大家认可 |
| 3 | 应加强相关培训 | 人不会干活是培训不够 |
| 4 | 应建立有效的沟通机制 | 信息不通畅导致配合出错 |
| 5 | 应进行监控和偏差分析 | 不监控就不知道偏了多少 |
| 6 | 应建立变更控制流程 | 没流程变更就是混乱 |
| 7 | 应及时更新项目文档 | 文档过时等于没有文档 |
| 8 | 应进行经验教训总结 | 不总结下次还犯同样的错 |

### 4.5 计算题答题标准格式 ★★★★★

**挣值题格式**：
```
第一步：列出已知数据
  BAC = XX万元，计划完成XX%，实际完成XX%，AC = XX万元

第二步：计算三个基本值
  PV = BAC × 计划完成% = ... = XX万元
  EV = BAC × 实际完成% = ... = XX万元
  AC = XX万元（题目给出）

第三步：计算绩效指数和偏差
  CPI = EV/AC = .../... = X.XX
  SPI = EV/PV = .../... = X.XX
  CV = EV-AC = ...-... = XX万元
  SV = EV-PV = ...-... = XX万元

第四步：写结论
  CPI = X.XX < 1，说明成本超支
  SPI = X.XX < 1，说明进度滞后

第五步：预测（如题目要求）
  判断：由题意"XXX"可知属于典型偏差/非典型偏差
  EAC = BAC/CPI = .../... = XX万元（典型）
  VAC = BAC-EAC = ...-... = XX万元
  结论：按当前趋势，完工时将超支XX万元
```

## 第五部分：高频必考详解要点

---

### 5.1 挣值分析 ★★★★★（每年必考，案例题+选择题）

> 详见第二部分公式详解。补充几个考试常见坑：

**坑1**：EV的计算方式
- 如果题目给了每个子任务的完成情况，要**逐个计算再加总**
- EV = 任务A预算×A完成% + 任务B预算×B完成% + ...

**坑2**：PV不一定等于BAC
- PV是"到检查时间点为止"计划应完成的工作量
- 只有项目结束时PV才等于BAC

**坑3**：必须先判断典型/非典型再算EAC
- 考试卷面上要写明判断依据
- 写错了后面全错

### 5.2 关键路径法 ★★★★★（每年必考）

> 详见第二部分网络图详解。补充关键考点：

**工期压缩的规则**：
1. 只能压缩**关键路径**上的活动
2. 优先压缩**每天增加费用最小**的
3. 压缩后必须检查是否产生新的关键路径
4. 净增成本 = 压缩增加费用 - 节省的间接费用×压缩天数

**延误问题的解法**：
- 关键路径上活动延误X天 → 项目延误X天
- 非关键路径活动延误X天 → 延误 = max(0, X - 总浮动时间)

### 5.3 WBS ★★★★★（高频案例题）

> **什么是WBS？**
> 把一个大项目像剥洋葱一样层层分解，直到每一块都小到能分配给一个人在1-2周内干完。

**100%规则**：WBS必须覆盖项目100%的工作，不多不少
**8-80规则**：最底层工作包应在8-80小时内能完成

**案例题中WBS最常见的3种错误**：
| 错误 | 正确做法 | 为什么 |
|------|---------|--------|
| 缺少"项目管理" | 加上 | 管理也是工作的一部分 |
| 缺少"培训" | 加上 | 系统上线需要培训用户 |
| 测试只写一项 | 分为单元/集成/系统/验收 | 测试有多个阶段不能混为一谈 |

### 5.4 变更管理 ★★★★★（高频案例题）

> **为什么变更管理是考试重点？**
> 因为90%的项目案例题都有"变更失控"的情节：客户随便改需求、开发人员随便改代码、改了没记录...

**核心要理解的3件事**：
1. **CCB是什么**：变更控制委员会，不是常设机构，需要审批变更时才召集，由项目发起人/PM/技术负责人/客户代表等组成
2. **谁能做什么**：客户只能提需求→PM评估影响→CCB审批→开发人员才能动手
3. **正确流程**：提出→记录→评估→审批→执行→更新文档→存入配置管理

### 5.5 配置管理 ★★★★★（高频选择+案例）

> **什么是配置管理？**
> 简单说就是"版本管理"。管好项目中产生的所有文档、代码、交付物的版本，确保不会搞混、不会丢失、能追溯历史。

**6个活动理解**：
| 活动 | 像什么 | 做什么 |
|------|--------|--------|
| 计划 | 制定图书馆借阅规则 | 定好怎么管版本的规矩 |
| 标识 | 给每本书贴编号 | 给每个管理对象编号建档 |
| 控制 | 借书要登记审批 | 要改东西必须走审批流程 |
| 状态记录 | 登记谁借了什么书 | 记录每次改了什么、谁改的 |
| 审计 | 查查有没有人偷书 | 检查有没有违规操作 |
| 发布 | 新书上架 | 正式发布某个版本 |

**3种库理解**：
| 库 | 生活类比 | 控制方式 |
|----|---------|---------|
| 开发库(动态) | 你电脑桌面的草稿文件 | 你自己想怎么改就怎么改 |
| 受控库(主库) | 公司共享网盘 | 上传需要审批 |
| 产品库(静态) | 寄给客户的光盘 | 只能看不能改 |

### 5.6 风险应对策略 ★★★★★（高频选择+案例）

| 策略 | 生活类比 | 适用场景 | 举例 |
|------|---------|---------|------|
| **规避** | 不上高速就不会出车祸 | 风险影响大+概率高 | 取消使用新技术 |
| **减轻** | 系安全带降低受伤程度 | 风险影响大但可降低 | 多做测试、提前培训 |
| **转移** | 买车险让保险公司赔 | 风险存在但可让别人扛 | 买保险、外包 |
| **接受** | 知道可能下雨但不带伞 | 风险影响小 | 制定应急预案 |

> **判断技巧**：
> - 题目说"完全消除了风险" → 规避
> - 题目说"降低了概率/影响" → 减轻
> - 题目说"让第三方承担" → 转移
> - 题目说"准备了预案" → 接受

### 5.7 质量七工具 ★★★★（高频选择题）

> 考试只需要区分每个工具的**关键用途**：

| 工具 | 一句话用途 | 考试关键词（看到就选它） |
|------|-----------|----------------------|
| **因果图**(鱼骨图) | 找出所有可能原因 | "所有原因""鱼骨""原因分析" |
| **帕累托图** | 找出少数主要原因 | "主要原因""二八法则""关键少数" |
| **直方图** | 看数据怎么分布 | "集中趋势""分散程度""分布" |
| **控制图** | 看过程是否在范围内 | "控制界限""上下限""过程稳定" |
| **散点图** | 看两个变量有没有关系 | "两个变量""相关性" |
| **流程图** | 了解做事步骤 | "过程""步骤""质量成本" |
| **核查表** | 记录/收集数据 | "收集""记录""统计" |

> **最常考的区分**：帕累托 vs 直方图
> - 都是垂直条形图
> - 帕累托 = 找"主要原因"（二八法则）
> - 直方图 = 看"分布特征"（集中+分散）

### 5.8 招投标数字 ★★★★（高频选择题）

| 环节 | 数字 | 理解（为什么是这个数） |
|------|------|---------------------|
| 公示期≥**5**日 | 5 | 给潜在投标者足够时间了解信息 |
| 预审通过≥**3**家 | 3 | 至少3家竞争才公平，不够要重新招 |
| 保证金≤**2%**且≤**80万** | 2%, 80万 | 防止门槛太高把小公司排除 |
| 评标委≥**5人单数** | 5 | 单数保证投票不会平票 |
| 竞争性谈判≥**3人单数** | 3 | 简化版评标，人少但也要单数 |
| 专家≥**2/3** | 2/3 | 确保评标的专业性 |
| 评标≤**3日**公布 | 3 | 不能拖太久 |
| 公示≥**3日** | 3 | 给公众监督的时间 |
| 异议**3日**答复 | 3 | 及时回应质疑 |
| 候选人≤**3人** | 3 | 有备选但不能太多 |
| **30日**内签合同 | 30 | 给准备时间但不能太长 |
| **5日**退保证金 | 5 | 及时退还没中标者的钱 |
| 履约保证金≤**10%** | 10% | 保证中标方能履约 |

> **故事记忆法**：
> 小明投标——看了**5**天公示，**3**家通过预审，交了**2%**(最多**80万**)保证金。
> **5**个人评标(专家≥**2/3**)，**3**天出结果，公示**3**天。
> 他在**3**个候选人中排第一，**30**天签合同，**5**天拿回保证金，交了**10%**履约金。
