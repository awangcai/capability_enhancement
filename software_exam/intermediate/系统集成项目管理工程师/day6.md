## 一、变更管理

### 1.1 变更管理基本原则（必记）
1. **基准管理**（变更的依据）
2. 建立**变更控制流程**
3. 建立**变更控制委员会（CCB）**（不常设机构）
4. 完整体现变更的**影响**（多维度分析）
5. 变更产生的相关文档纳入**配置管理**

### 1.2 变更申请类型
- **纠正措施**：使项目绩效和计划保持一致
- **预防措施**：使项目未来绩效和计划一致
- **缺陷补救**：修改不一致的产品/组件
- **更新**：对文件进行更新，反映变动

### 1.3 变更权限
- **客户**：只能提出范围变化的需求
- **项目经理**：解答可行性、成本等
- **投资人/CCB**：才能批准变更（除非授权他人）

### 1.4 变更管理流程

```
提出变更请求
    ↓
记录变更（变更日志）
    ↓
评估变更影响（多维度）
    ↓
CCB审批
    ↓
批准 → 实施变更 → 更新文档 → 纳入配置管理
拒绝 → 通知申请人 → 记录原因
```

### 1.5 变更控制的输入/输出

| 类别 | 内容 |
|------|------|
| 输入 | 项目管理计划、变更请求、工作绩效报告 |
| 工具与技术 | 会议、变更控制工具、专家判断 |
| 输出 | 批准的变更请求、变更日志、计划/文件更新 |

> **重要**：基线形成之后才涉及变更

## 二、配置管理

### 2.1 配置管理六个活动（必记）

| 序号 | 活动 | 核心内容 |
|------|------|---------|
| 1 | 管理**计划** | 了解组织结构中环境和单元之间的关系 |
| 2 | 配置**标识** | 识别配置项，建立基线 |
| 3 | 配置**控制** | 管理软件生命周期的变更 |
| 4 | **状态**记录 | 标记、收集、维护、报告配置状态信息 |
| 5 | 配置**审计** | 独立评价是否遵从规则，确保有效性 |
| 6 | **发布**管理与交付 | 创建特定交付版本，关键在于软件库 |

### 2.2 配置审计类型

| 类型 | 审计内容 |
|------|---------|
| **功能配置审计**（审计一致性） | 开发是否完成、是否达到规定功能性能、文档是否符合 |
| **物理配置审计**（审计完整性） | 交付配置项是否存在、是否包含所有必须项目 |

### 2.3 配置库分类（必记）

| 配置库 | 别名 | 内容 | 控制者 |
|--------|------|------|--------|
| **开发库** | 动态库、程序员库、工作库 | 开发人员当前正在开发的内容 | 开发人员自行控制 |
| **受控库** | 主库 | 当前基线+对基线的变更 | 完全配置管理 |
| **产品库** | 静态库、发行库 | 已发布的各种基线存档 | 完全配置管理 |

> **记忆**：开发库=动态/工作 → 受控库=主库 → 产品库=静态/发行

### 2.4 版本号规则

| 状态 | 版本号 |
|------|--------|
| 草稿 | 0.01-0.99 |
| 正式（首次） | 1.0 |
| 正式（小幅升级） | 1.1-1.9 |
| 正式（大幅升级） | 2.X, 3.X |
| 修改状态 | X.YZ |

## 三、采购管理

### 3.1 采购的四个过程
1. **采购管理规划**（含自购/外购分析）
2. **采购实施**
3. **采购控制**
4. **结束采购**（含采购审计）

### 3.2 合同类型（必记）

| 类型 | 特点 | 风险承担 |
|------|------|---------|
| **固定总价** | 价格不变 | 卖方承担风险 |
| **总价加激励** | 达到目标给奖励 | 风险共担 |
| **总价加经济价格调整** | 长期合同，允许调价 | 风险共担 |
| **成本补偿** | 全部成本+利润 | 买方承担风险 |
| **工料合同** | 按工时和材料计费 | 买方承担风险 |
| **订购单** | 标准化产品，单边合同 | - |

**成本补偿合同适用**：
- 需要立刻开展工作的项目
- 技术经济指标未明确的项目
- 风险大的项目

### 3.3 采购谈判要点
- 签署的合同最终版 = 达成协议
- 以双方签署文件（合同/协议）为**结束标志**
- 简单采购可用固定不变合同
- 项目经理**可以不是**合同主谈人

## 四、招投标（关键数字必记）★★★

### 4.1 招标

| 事项 | 数字要求 |
|------|---------|
| 公示期 | ≥ **5** 日 |
| 通过预审单位 | ≥ **3** 家（不足重新招标） |
| 投标保证金 | ≤ **2%** 且 ≤ **80万** |
| 标底 | 不必须、保密、唯一 |

### 4.2 采购方式

| 方式 | 适用条件 |
|------|---------|
| **公开招标** | 默认方式 |
| **邀请招标** | 特定条件下限定投标人 |
| **竞争性谈判** | 无人投标/重新招标未成立/技术复杂/紧急 |
| **单一来源采购** | 唯一供应商 |
| **询价** | 标准化产品 |

### 4.3 评标

| 事项 | 数字要求 |
|------|---------|
| 常规招标评标委 | **5人以上单数** |
| 竞争性谈判评标 | **3人以上单数** |
| 技术/经济专家比例 | ≥ **2/3** |
| 评标公布 | ≤ **3日**内 |
| 公示时间 | ≥ **3日** |
| 异议答复 | **3日**内 |

### 4.4 中标

| 事项 | 数字要求 |
|------|---------|
| 中标候选人 | ≤ **3人**（标明排序，不公布） |
| 签合同期限 | **30日**内 |
| 退保证金期限 | **5日**内 |
| 履约保证金 | ≤ **10%** |

### 4.5 数字速记总结

```
公示≥5日，预审≥3家
保证金≤2%且≤80万
评标：常规5+单数，竞争3+单数
专家≥2/3
评标≤3日公布，公示≥3日，异议3日答复
候选人≤3人，30日内签合同，5日退保证金，履约≤10%
```

### 4.6 其他注意事项
- 不能将**主体、核心工程**分包
- 非主体工程分包应在**投标文件中说明**
- 两阶段招标：一阶段交技术建议（不带标价），二阶段交报价

1. 变更控制委员会（CCB）是（）机构？
   A. 常设 B. 不常设 C. 临时 D. 虚拟
   **答案：B**

2. 审计配置项是否存在、是否包含所有必须项目属于（）？
   A. 功能配置审计 B. 物理配置审计 C. 配置标识 D. 配置控制
   **答案：B**

3. 开发人员当前正在开发的配置实体保存在（）？
   A. 产品库 B. 受控库 C. 开发库 D. 版本库

4. 投标保证金不得超过项目估算价的（）？
   A. 1% B. 2% C. 5% D. 10%
   **答案：B**

5. 评标委员会中技术、经济专家应不少于成员总数的（）？
   A. 1/2 B. 2/3 C. 3/4 D. 1/3
   **答案：B**

6. 中标人应在中标通知书发出后（）日内签订合同？
   A. 15 B. 20 C. 30 D. 60
   **答案：C**
