# 案例分析题答题技巧（详解版）

> 本文帮助你理解案例题"是什么"以及"怎么答"。每个技巧都有详细解释，把你当小白来讲。
> ★★★★★=必须掌握  ★★★★=重点掌握  ★★★=了解

---

## 一、案例题是什么？★★★★★

### 1.1 考试形式

下午考试给你4道大题，每题一个"故事"：
- **故事内容**：描述一个项目从开始到出问题的过程（2-3段文字）
- **然后问你**：这个项目存在什么问题？应该怎么改？有时还有计算
- **时间**：150分钟做4题，每题约35-40分钟
- **满分**：75分，45分及格

### 1.2 题型分类

| 题型 | 长什么样 | 怎么答 | 出现频率 |
|------|---------|--------|---------|
| **找问题** | "该项目存在哪些问题？" | 对照模板逐点列出问题 | ★★★★★极高 |
| **给建议** | "应如何改进？" | 针对每个问题给出对策 | ★★★★★极高 |
| **计算** | 给数据表，求指标 | 写公式→代入→结果→结论 | ★★★★★极高 |
| **概念** | "XX包含哪些内容？" | 直接背诵标准知识点 | ★★★★高 |
| **判断** | "判断对错并说明理由" | 先判断，再解释 | ★★★中 |

### 1.3 评分方式——踩点给分

> **关键理解**：阅卷老师手里有一份"标准答案"，列了8-10个得分点。
> 你写的每一条如果和某个得分点吻合就给分，多写不扣分。
> 所以：**多写=多踩点=多得分，少写=少踩点=少得分，不写=0分**

## 二、答题五原则 ★★★★★

| 原则 | 怎么做 | 为什么这样做 |
|------|--------|-------------|
| **多写要点** | 宁愿多写3条也别少写1条 | 踩点给分，多写不扣分 |
| **分点编号** | 用(1)(2)(3)或1.2.3.清晰列出 | 阅卷老师能快速找到得分点 |
| **先总后分** | 第一句写结论，后面展开 | 即使展开不够好，结论也能得分 |
| **不留空白** | 完全不会也要写相关知识 | 写了有可能得1-2分，空着必然0分 |
| **计算写全** | 公式→代入→结果→单位→结论 | 每一步都可能是独立的得分点 |

> **反面教材**：
> - ❌ 只写"项目管理不规范"（太笼统，没有具体到点）
> - ✅ 写"项目管理计划由项目经理一人编制，未组织全体干系人共同参与编制和评审"（具体、踩点）

## 三、"找问题"题型——万能五步法 ★★★★★

> 拿到案例题，按以下5步从头到尾扫描故事文本，基本能找出所有问题。

### Step 1：看身份（项目经理是谁？）★★★★★

| 在故事中找什么 | 可能存在的问题 |
|---------------|---------------|
| "XX是一名资深程序员，被任命为项目经理" | PM缺乏项目管理经验和培训 |
| "XX身兼数职" | 工作负荷过重，精力不足 |
| "XX独自承担了..." | 一个人干多个人的活 |

> **理解**：很多案例题的第一句就埋了"坑"——PM背景不合适

### Step 2：看过程（计划怎么编的？）★★★★★

| 在故事中找什么 | 可能存在的问题 |
|---------------|---------------|
| "小王根据自己的经验编制了计划" | 计划由一人编制，未全员参与 |
| "编完后就开始执行" | 计划未经评审 |
| "没有制定XX计划" | 缺少相应管理计划 |

> **理解**：计划是项目的基石，必须全员参与+评审通过才能执行

### Step 3：看变更（需求改了怎么处理的？）★★★★★

| 在故事中找什么 | 可能存在的问题 |
|---------------|---------------|
| "客户直接找开发人员提出修改" | 变更未经PM和CCB |
| "开发人员直接修改了代码" | 变更未经审批 |
| "改完后没有更新文档" | 变更后未更新相关文档 |
| 没有提到CCB | 未建立变更控制流程/CCB |

> **理解**：变更不走流程=项目失控。正确流程：提出→记录→评估→审批→执行→更新

### Step 4：看监控（有没有人盯着？）★★★★

| 在故事中找什么 | 可能存在的问题 |
|---------------|---------------|
| "直到XX阶段才发现问题" | 缺少过程监控，问题发现太晚 |
| "进度严重滞后" | 未进行进度监控和偏差分析 |
| "成本超支" | 未进行成本监控 |

> **理解**：不监控就像开车不看仪表盘，等出事才知道

### Step 5：看沟通（大家有没有充分交流？）★★★★

| 在故事中找什么 | 可能存在的问题 |
|---------------|---------------|
| "客户不满意""领导不满意" | 沟通不充分 |
| "团队成员不知道..." | 信息传递不及时 |
| "只通过邮件通知" | 沟通方式单一 |
| "冲突通过强制手段解决" | 冲突管理不当 |

> **理解**：很多项目问题的根源是"该知道的人不知道"

## 四、各主题专用答案模板 ★★★★★

> 案例题考某个领域时，除了万能五步法，还要加上该领域的专属问题。

### 4.1 整体管理案例 ★★★★★

**典型场景**：PM没经验、计划不规范、变更失控

**答题模板（从中选6-8条写）**：
| 编号 | 问题 | 理解 |
|------|------|------|
| 1 | PM缺乏项目管理经验/培训 | 技术牛≠管理牛 |
| 2 | 项目管理计划由一人编制，应全员参与 | 不能自己拍脑袋决定 |
| 3 | 计划未经评审就直接执行 | 没有质量检查的计划可能有漏洞 |
| 4 | 未建立变更控制流程/未组建CCB | 没有审批机制 |
| 5 | 执行偏离计划时未走变更流程 | 变了就要走流程 |
| 6 | 未进行有效的项目监控 | 不盯着就会出事 |
| 7 | 未建立有效的沟通机制 | 信息不通畅 |
| 8 | 相关文档未及时更新 | 文档过时=没有文档 |
| 9 | 未进行经验教训总结 | 不总结就不会进步 |

### 4.2 范围管理案例 ★★★★★

**典型场景**：需求蔓延、WBS不完整

**答题模板**：
| 编号 | 问题 | 理解 |
|------|------|------|
| 1 | WBS分解不完整（缺少管理/培训/测试子类） | 漏了工作 |
| 2 | WBS未经全体干系人确认 | 别人不认可的分解等于没有 |
| 3 | 缺少范围基准（说明书+WBS+词典） | 没有"做多少事"的标准 |
| 4 | 项目边界未明确定义 | 不知道什么不该做 |
| 5 | 需求变更未走变更流程就直接改 | 改需求不走流程=范围蔓延 |
| 6 | 范围变更后未更新WBS和计划 | 文档和实际不一致 |
| 7 | 未进行范围确认（验收） | 做完了没让客户签字确认 |

### 4.3 进度/成本管理案例（含计算）★★★★★

**典型场景**：给一张数据表，要求计算挣值指标

**计算题标准答题格式**：
```
已知条件：
  BAC = XX万元
  当前时间点：第X月末
  计划完成：XX%
  实际完成：XX%
  实际花费(AC) = XX万元

第一步——计算基本值：
  PV = BAC × 计划完成% = XX × XX% = XX万元
  EV = BAC × 实际完成% = XX × XX% = XX万元
  AC = XX万元

第二步——计算绩效指数：
  CPI = EV ÷ AC = XX ÷ XX = X.XX
  SPI = EV ÷ PV = XX ÷ XX = X.XX

第三步——计算偏差：
  CV = EV - AC = XX - XX = XX万元
  SV = EV - PV = XX - XX = XX万元

第四步——结论：
  CPI = X.XX < 1（或>1），表明项目成本超支（或节约）
  SPI = X.XX < 1（或>1），表明项目进度滞后（或提前）

第五步——预测（如果题目要求）：
  由题意"后续将保持当前效率"可知，属于典型偏差。
  EAC = BAC ÷ CPI = XX ÷ X.XX = XX万元
  ETC = EAC - AC = XX - XX = XX万元
  VAC = BAC - EAC = XX - XX = XX万元
  结论：按当前趋势，项目完工时预计总花费XX万元，超支XX万元。
```

> **计算题得分要点**：
> 1. 写公式（即使简单也写）→ 有分
> 2. 代入数据 → 有分
> 3. 写出结果 → 有分
> 4. 带单位（万元/天）→ 不带可能扣分
> 5. 写结论（超支/节约/滞后/提前）→ 有分

### 4.4 质量管理案例 ★★★★

**典型场景**：Bug频出、测试不充分、质量流于形式

**答题模板**：
| 编号 | 问题 | 理解 |
|------|------|------|
| 1 | 缺少质量管理计划 | 没有质量标准就没法管 |
| 2 | 质量规划应全体干系人参与 | 标准要大家认可 |
| 3 | 未制定质量测量指标和核对单 | 不知道"好"的标准是什么 |
| 4 | 开发人员自己测试自己代码 | 自己检查自己肯定不客观 |
| 5 | 未进行质量审计（质量保证） | 没有预防性检查 |
| 6 | 未采用合理的质量工具和技术 | 七工具没用起来 |
| 7 | 未收集质量过程中的绩效数据 | 没数据就没法改进 |

### 4.5 风险管理案例 ★★★★

**典型场景**：风险发生了才后悔没提前预防

**答题模板**：
| 编号 | 问题 | 理解 |
|------|------|------|
| 1 | 缺乏风险管理意识 | 觉得不会出事所以不管 |
| 2 | 未编制风险管理计划 | 没有管风险的章法 |
| 3 | 未进行风险识别/未建风险登记册 | 不知道有什么风险 |
| 4 | 未做定性/定量分析 | 知道有风险但没评估严重程度 |
| 5 | 风险应对措施不全面/不有效 | 准备的预案没用 |
| 6 | 应对措施没有分配责任人 | 知道该做但没人负责 |
| 7 | 未定期风险再识别和监控 | 只识别一次不持续跟踪 |
| 8 | 出现了XX问题→说明应对不到位 | 事实证明准备不够 |

### 4.6 变更管理案例 ★★★★★

**典型场景**：客户直接找开发改东西、改了没记录

**答题模板**：
| 编号 | 问题 | 理解 |
|------|------|------|
| 1 | 未建立变更控制流程 | 没有规矩 |
| 2 | 未组建CCB | 没有审批机构 |
| 3 | 客户/成员绕过PM和CCB直接变更 | 跳过了所有审批环节 |
| 4 | 变更未经影响分析就执行 | 不知道改了会有什么后果 |
| 5 | 变更未经CCB审批 | 没人拍板 |
| 6 | 变更后未更新相关文档 | 文档和实际不一致了 |
| 7 | 变更记录不完整 | 以后查不到改了什么 |
| 8 | 变更后未通知所有干系人 | 别人不知道改了 |

## 五、"给建议"题型——对策模板 ★★★★★

> "给建议"就是把"找问题"反过来说。每个问题对应一个建议。

### 5.1 万能对策框架

```
1. 编制/完善XX管理计划
2. 组织全体干系人参与评审
3. 加强XX方面的培训
4. 建立有效的沟通机制
5. 建立变更控制流程，组建CCB
6. 加强监控，定期审查进展
7. 及时更新项目文档
8. 进行经验教训总结
```

### 5.2 进度滞后的对策（高频）★★★★★

```
1. 赶工——增加资源投入
2. 快速跟进——安排可并行的工作同时进行
3. 使用高素质资源或更有经验的人员
4. 改进工作方法或技术，提高效率
5. 加强质量管理，减少返工
6. 在客户许可前提下，减少活动范围或降低要求
```

### 5.3 变更管理的正确做法（高频）★★★★★

```
1. 提出变更请求并书面记录
2. 对变更进行影响分析（范围、进度、成本、质量）
3. 提交CCB审批
4. CCB批准后方可执行变更
5. 更新项目管理计划和所有相关文档
6. 通知所有相关干系人
7. 变更文档纳入配置管理
```

## 六、判断题和英语题技巧 ★★★

### 6.1 判断题

| 策略 | 原理 |
|------|------|
| 看到"所有""全部""一定" | 倾向错（太绝对的通常不对） |
| 看到"可以""可能""一般" | 倾向对（留有余地的通常对） |
| 完全拿不准 | **优先选"对"**（统计上对的概率更高） |

### 6.2 英语题

| 策略 | 原理 |
|------|------|
| 看不懂全文 | 找关键词（Scope/Cost/Risk等）和选项匹配 |
| 选项都像 | 选题干关键词重复最多的那个选项 |

## 七、时间分配和书写规范 ★★★★

### 7.1 时间分配
```
浏览全部题目：5分钟（先看哪题有计算，心里有数）
计算题：40分钟（确保正确，这是稳定得分）
分析题1：35分钟
分析题2：35分钟
最后一题：35分钟
```

### 7.2 书写规范
- 字迹工整（阅卷老师看不清就不给分）
- 分点作答，编号清晰
- 每个要点1-2句话即可，不需要写作文
- 计算题单独成段，公式单独一行
- 网络图用直尺画

### 7.3 常见扣分点
| 扣分点 | 怎么避免 |
|--------|---------|
| 计算题忘写单位 | 每个数字后面跟单位（万元/天/条） |
| 挣值分析忘判断偏差类型 | 算EAC前先写"属于典型/非典型偏差" |
| 找问题只写了2-3个 | 至少写6-8个（用五步法扫描） |
| 答案太笼统 | 具体说明是什么问题、违反什么原则 |
| 网络图正逆推搞混 | 默念"正推取大逆推取小" |
| 留空白 | 写万能保底8条凑分 |

## 八、得分保底策略 ★★★★★

> 即使碰到完全没见过的题，也能用这些策略拿到一些分数。

### 8.1 完全不会的分析题——写万能8条

```
1. 应编制XX管理计划
2. 应组织全体干系人参与评审
3. 应加强相关培训
4. 应建立有效的沟通机制
5. 应进行监控和偏差分析
6. 应建立变更控制流程
7. 应及时更新项目文档
8. 应进行经验教训总结
```

> 这8条几乎适用于任何管理类案例题，写上去总能蹭到2-4分

### 8.2 计算题写不出结果——至少写公式

即使算不对，写出正确的公式也可能有1-2分：
```
CPI = EV/AC
SPI = EV/PV
EAC = BAC/CPI（典型偏差）
```

### 8.3 概念题记不全——写你记得的

比如问"风险管理包含哪些过程"，你只记得4个也写4个：
```
(1) 风险管理规划
(2) 风险识别
(3) 风险应对
(4) 风险控制
```
> 写4个至少得4个的分，不写就是0分
